# Coordenação da equipe

## Papel do coordenador

O coordenador não precisa fazer tudo nem decidir tudo.

Sua função é manter cinco coisas claras:

```text
Objetivo
→ Prioridades
→ Responsáveis
→ Dependências
→ Progresso
```

O objetivo é fazer a equipe avançar na direção certa, e não apenas manter todos ocupados.

## 1. Entender o problema

Antes de pensar em solução:

- leia o enunciado com a equipe;
- identifique quem possui o problema;
- defina qual problema precisa ser resolvido;
- registre restrições e entregáveis;
- separe fatos de suposições.

Peça para cada integrante explicar o problema em uma frase. Se as respostas forem muito diferentes, alinhem o entendimento antes de começar.

## 2. Conhecer a equipe

Descubra o que cada pessoa consegue fazer bem:

- desenvolvimento;
- pesquisa;
- negócio;
- planilhas e dados;
- escrita;
- apresentação;
- design;
- testes.

Distribua trabalho por capacidade, não apenas pelo curso da pessoa.

## 3. Delegar resultados

Toda tarefa deve possuir:

- um responsável principal;
- um resultado esperado;
- critérios de aceite;
- dependências conhecidas.

Evite tarefas vagas como "pesquisar mercado".

Prefira resultados verificáveis, como "identificar três soluções semelhantes e resumir uma diferença relevante de cada uma".

## 4. Evitar o gargalo do desenvolvedor

Se houver apenas um desenvolvedor, ele deve concentrar tempo em:

- implementação;
- integração;
- decisões técnicas;
- depuração;
- automações necessárias.

Outros integrantes podem assumir:

- requisitos;
- regras de negócio;
- pesquisa;
- preparação de dados;
- validação;
- documentação;
- apresentação.

Antes de passar uma tarefa ao desenvolvedor, pergunte:

> Isso realmente exige programação?

## 5. Identificar dependências e bloqueios

O coordenador precisa saber quem está esperando quem.

Quando alguém estiver bloqueado, registre:

- o que está impedido;
- por que está impedido;
- o que é necessário para continuar;
- quem pode ajudar.

Tarefas que desbloqueiam várias outras recebem prioridade.

## 6. Acompanhamento curto

Em cada ponto de acompanhamento, pergunte:

1. O que foi concluído?
2. Qual é o próximo resultado?
3. Existe algum bloqueio?

Depois verifique:

- algum item importante está parado?
- alguém está esperando outra pessoa?
- existem tarefas demais em andamento?
- o escopo ainda cabe no prazo?

## 7. Controlar o escopo

Quando surgir uma nova ideia, pergunte:

1. Qual problema ela resolve?
2. É necessária para a entrega?
3. O que será atrasado se ela entrar agora?

Classifique mentalmente como:

- **essencial**;
- **importante**;
- **não agora**.

O coordenador também é responsável por dizer "não agora".

## 8. GitHub Projects — Kanban

O GitHub Projects será o painel operacional da equipe.

Use somente quatro colunas:

```text
Backlog
→ Em andamento
→ Revisão
→ Concluído
```

### Backlog

Trabalho identificado que ainda não está sendo executado.

Antes de sair do Backlog, a tarefa deve possuir:

- responsável;
- objetivo claro;
- critérios de aceite;
- dependências conhecidas.

### Em andamento

Existe alguém trabalhando ativamente na tarefa.

Evite que uma pessoa mantenha várias tarefas principais simultaneamente.

### Revisão

O resultado existe e precisa ser:

- testado;
- revisado;
- validado;
- aprovado.

Quem produziu o resultado não deve ser a única pessoa a validá-lo quando houver outra pessoa disponível.

### Concluído

Os critérios de aceite foram atendidos e não existe pendência relevante.

## 9. Uso diário do Kanban

O coordenador deve olhar o quadro e responder:

- existe alguma tarefa essencial parada?
- existe alguém bloqueado?
- existe trabalho demais em "Em andamento"?
- o que precisa ser revisado?
- o que realmente foi concluído?

Issues representam trabalho. O GitHub Projects mostra o estado desse trabalho.

## 10. Fase final

Perto da entrega:

- pare de aceitar itens não essenciais;
- finalize o núcleo;
- valide;
- corrija problemas críticos;
- ensaie a apresentação.

A equipe deve conseguir explicar:

1. qual era o problema;
2. o que foi proposto;
3. como a solução responde ao problema;
4. quais são suas limitações.
